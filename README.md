# AIGameAssistant

ИИ-ассистент для настольных игр. Каталог с поиском, категориями и избранным, просмотр PDF-правил, история диалогов и потоковые ответы ИИ. Администратор управляет играми, пользователями, моделями OpenRouter и настройками ассистента. Гостевой чат доступен без регистрации, с историей в браузере. Ответы содержат TL;DR и подробное объяснение; поддерживаются текстовые PDF и сканированные правила.

## Стек

- Frontend: Next.js 16 App Router, React 19, TypeScript, FSD, SCSS Modules.
- Backend: Java 21, Spring Boot 3.5, PostgreSQL, Liquibase.
- ИИ: OpenRouter. Локальная почта: Mailpit.
- Проверки: ESLint, Stylelint, Prettier, Jest и Playwright.
- Запуск: Docker Compose.

## Запуск

Нужны Docker и Compose v2. В корне проекта:

```bash
cp .env.example .env
```

Заполните `.env`: `POSTGRES_PASSWORD`, разные `JWT_SECRET_ACCESS` и `JWT_SECRET_REFRESH`, а также `ADMIN_EMAIL`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`. Каждый JWT-секрет сгенерируйте отдельно командой `openssl rand -base64 64`. Администратор создаётся, если такого email ещё нет.

```bash
docker compose up --build -d --wait --wait-timeout 240
```

Сайт: [http://localhost](http://localhost). Порт задаёт `APP_PORT`; `APP_PUBLIC_URL` должен совпадать с адресом сайта в браузере, включая схему и порт. Для публичного размещения используйте HTTPS. Секреты из `.env` не добавляйте в Git.

Основные команды из корня:

```bash
docker compose logs -f          # журналы сервисов
docker compose up --build -d    # пересобрать и обновить приложение
docker compose down            # остановить, сохранив БД и файлы
```

Для разработки frontend нужны Node.js 22.13+ и npm 10+. Сначала запустите backend:

```bash
APP_PUBLIC_URL=http://localhost:3000 docker compose up --build -d backend
```

API доступен только локально на `127.0.0.1:8080`. `APP_PUBLIC_URL` в команде задаёт адрес frontend для ссылок из писем.

Затем в другом терминале:

```bash
cd frontend
cp .env.example .env.local
npm ci
npm run dev
```

Frontend: [http://localhost:3000](http://localhost:3000). В `.env.local` по умолчанию указаны `BACKEND_URL=http://127.0.0.1:8080` и `APP_PUBLIC_URL=http://localhost:3000`.

Основные команды из `frontend/`:

```bash
npm run check          # lint, TypeScript, тесты и production build
npm run format         # форматирование Prettier
npm run build          # production-сборка
npm exec playwright install chromium  # один раз перед E2E
npm run test:e2e        # браузерные тесты после build
```

Backend-тесты: `cd backend && ./gradlew test`.

## Подключение ИИ-моделей

Для подключения ИИ задайте `OPENROUTER_API_KEY` в корневом `.env` и запустите приложение командой `docker compose up --build -d`. Для платных моделей и распознавания сканов нужен баланс OpenRouter.

Модели и пользовательские предпочтения хранятся в PostgreSQL. При первом запуске каталог из `backend/config/ai-models.yaml` импортируется в БД с внутренними ID, названиями, доступностью и пределами ответа. Этот файл служит для начального заполнения; дальнейшее управление выполняется в админке. Без файла начального каталога модели нужно добавить вручную.

Подключение и управление:

1. Войдите администратором и откройте **Настройки → Модели → ＋**.
2. Найдите модель по названию или ID в каталоге OpenRouter. Для каждой модели указана стоимость входных и выходных токенов в USD за 1 млн токенов. Если стоимость недоступна, отображается «нет данных». Каталог и цены обновляются раз в час.
3. Укажите отображаемое название до 100 символов и предел ответа: 256–32768 токенов в пределах возможностей модели.
4. Нажмите **Добавить**. Первая добавленная модель становится основной.

В таблице моделей доступны выбор основной модели, включение, отключение и удаление с подтверждением. Дубликаты запрещены. При отключении или удалении основной модели система выбирает другую включённую модель и сбрасывает недоступные пользовательские предпочтения. Последнюю включённую модель отключить или удалить нельзя.

Основная инструкция ассистенту редактируется в **Настройки → Промпт**. Ответы строятся в формате **TL;DR** — краткий вывод из 1–3 предложений — и **Подробно** с пояснениями, условиями и исключениями. Для каждого ответа используются актуальная инструкция, подготовленные правила и история диалога. При недостатке сведений ассистенту предписано сообщить об этом; точность ответа зависит от выбранной модели.

Гостевой чат доступен по кнопке **Задать вопрос** в каталоге, на странице `/games/ai/<gameId>`:

- До 5 принятых запросов в сутки на гостевой идентификатор, общий для всех игр. Квота сбрасывается в 00:00 UTC; интервал между вопросами — минимум 10 секунд.
- До 1000 символов в вопросе и 2048 выходных токенов. Ответы даёт основная модель.
- Последние 10 сообщений сохраняются в браузере отдельно для каждой игры; для ответа используются максимум 8 предыдущих сообщений.
- Очистка истории не сбрасывает квоту. Принятый запрос расходует попытку, в том числе при ошибке во время обработки.
- Зарегистрированным пользователям доступны история диалогов в аккаунте, выбор модели и вопросы до 10000 символов. Гостевая история остаётся в браузере.

Гостевые квоты хранятся в PostgreSQL. `GUEST_DAILY_BUDGET=200` задаёт общий суточный бюджет гостевых запросов приложения. Необязательный `GUEST_CLIENT_IP_HEADER` включает дополнительный лимит 20 запросов в сутки на IP-адрес. Настраивайте его за доверенным reverse proxy, который перезаписывает заголовок адресом клиента и закрывает прямой доступ к сервисам. Адреса хранятся в виде HMAC. Общий бюджет ограничивает расходы при смене гостевого идентификатора или адреса.

PDF-правила загружаются через форму игры в админке и обрабатываются в фоне. Текстовые документы читаются через PDFBox; сканы и смешанные документы распознаются с помощью OpenRouter `mistral-ocr`. Ограничения: 10 МБ, 100 страниц, 200000 символов подготовленного Markdown.

В таблице игр отображается состояние подготовки правил: **В очереди**, **Обработка PDF / OCR**, **Готовы для ИИ** или сообщение об ошибке. При ошибке доступна повторная обработка. Отправка вопросов становится доступной после подготовки документа.

Исходные PDF, Markdown и кеш распознавания хранятся в `uploads`. Идентичные файлы используют кеш по SHA-256.

Для доступа к OpenRouter можно настроить SOCKS5-прокси: `PROXY_HOST`, `PROXY_PORT`, `PROXY_LOGIN`, `PROXY_PASSWORD`. Для прямого подключения оставьте `PROXY_HOST` пустым.

## Подключение почты

По умолчанию письма доступны в локальном [Mailpit](http://localhost:8025). Для отправки через Gmail укажите в корневом `.env`:

```dotenv
SPRING_MAIL_HOST=smtp.gmail.com
SPRING_MAIL_PORT=587
EMAIL_ADDRESS=sender@example.com
EMAIL_APP_PASSWORD=your-app-password
SMTP_AUTH=true
SMTP_STARTTLS=true
APP_PUBLIC_URL=https://your-domain.example
```

`EMAIL_ADDRESS` используется как SMTP-логин и отправитель. Подставьте собственные значения и примените `docker compose up -d backend`. При изменении публичного адреса также пересоздайте frontend: `docker compose up -d frontend`.
